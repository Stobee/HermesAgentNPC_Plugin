Hermes Agent NPC UE5 Plugin Specification

언리얼 엔진 5.8 C++ 모듈과 완제품 블루프린트 에셋이 독립 패키지(Plugins/HermesAgentNPC/)로 결합된 AI Agent NPC 전용 플러그인 사양서입니다. 프로젝트 설정(UHermesSettings)을 통한 호스트/포트 제어 및 강력한 파라미터 안전 검증 기능을 내장하고 있습니다.

01

프로젝트 개요

💡 구현 목적
외부 Hermes AI 백엔드 서버(설정 기반 호스트/포트)와 통신하여 플레이어와의 자유형 대화 및 4종의 화이트리스트 인게임 액션 지시(이동, 추적, 인벤토리, 아이템 주고받기)를 비동기로 구동하는 완전 독립형 플러그인을 제공합니다.
🛡️ 핵심 경쟁력
  • 독립형 Plugins/HermesAgentNPC/ 패키지로 다른 UE5 프로젝트에 즉시 이식 가능
  • 에디터 Project Settings 및 Config/DefaultGame.ini를 통한 서버 주소 외부 전역 설정화
  • 완제품 블루프린트(BP_HermesNPC, WBP_HermesDialogue) 내장 (CanContainContent: true)
  • 파라미터 하드 바운드, 토큰 버킷 레이트 리미터, 큐 상한 제어로 악성 피어 방어
  • 서버 발급 신원(player_id / session_token)의 SaveGame 보관 및 15초 액션 타임아웃 디스패처

03

3계층 아키텍처 설계

1. Transport Layer
FHermesFrameCodec, FFrameAccumulator, FHermesSocketWorker로 구성되며 4바이트 길이 프리픽스 파싱, GetAddressInfo 기반 DNS 해석 및 TQueue 백그라운드 송수신을 담당합니다.
2. Connection Layer
UHermesConnectionSubsystem이 UGameInstanceSubsystem으로 동작하여 연결 수명주기, 서버 발급 자격 증명의 SaveGame 보관, identify 핸드셰이크 및 보류 발화 상한(PushBounded)을 처리합니다.
3. Dispatch & Gameplay Layer
UHermesActionDispatcher가 액션 파라미터를 하드 바운드로 검증하고, 토큰 버킷 레이트 리미터를 거쳐 4종의 IHermesActionHandler (MoveTo, Follow, Inventory, Transfer) 및 UMG 대화 위젯으로 라우팅합니다.
대상 범위 — 단일 NPC: 프로토콜에 NPC 식별자가 존재하지 않으므로 하나의 연결은 정확히 하나의 NPC를 조종합니다. 활성 NPC는 AHermesNPCCharacter의 Auto Register As Active Npc 체크박스 또는 BecomeActiveHermesNpc() 호출로 프로젝트가 지정하며, 새 NPC가 등록되면 UHermesActionDispatcher::ResetHandlers()로 이전 배선을 제거하고 경고를 남깁니다. 다중 대화형 NPC는 설계상 범위 밖입니다.
04

TCP 소켓 프레이밍 규약

프레이밍 구조: 모든 네트워크 패킷은 TLS 1.2+ 위에서 [4바이트 Big-Endian Length Prefix] + [UTF-8 JSON Body] 구조를 따릅니다. (최대 바디 크기: 1,048,576 Bytes / 1 MiB) 
+----------------------------------+-----------------------------------------------+
| Length Prefix (4 Bytes uint32)   | JSON Message Payload (UTF-8 Encoded String)  |
| Big-Endian Order                 | Max Length: 1,048,576 Bytes                   |
+----------------------------------+-----------------------------------------------+

전송 계층은 IHermesTransport로 추상화되어 있어 프레이밍·큐·백오프 로직은 평문과 TLS를 구분하지 않습니다. 실제 구현은 FHermesPlainTransport(개발용 평문)와 FHermesTlsTransport(OpenSSL 기반 TLS) 둘입니다.

평문 폴백이 없습니다. TLS 핸드셰이크나 인증서 검증에 실패하면 연결을 닫고 백오프 재연결에 맡길 뿐, 평문으로 다운그레이드하지 않습니다. WITH_SSL이 없는 플랫폼에서 TLS를 요구하면 연결 자체를 거부합니다.
🔐

TLS 전송 및 보안 모델

검증 정책

TLS 사용 여부는 서버와 협상하지 않으며 클라이언트 설정만으로 결정됩니다. 검증 방식은 HermesTls::ResolveVerifyMode가 설정값을 보고 셋 중 하나를 고릅니다.

서버 인증서 채울 설정 검증 방식
자체 서명 (LAN 사설 IP) TlsPinnedPublicKeyHashes 공개키(SPKI) SHA-256 핀 고정
사설 CA 발급 TlsPrivateCaPath 해당 CA 신뢰 추가 후 표준 체인 + 호스트명 검증
공인 CA 발급 (둘 다 비움) 시스템 루트 CA로 표준 체인 + 호스트명 검증
핀이 하나라도 있으면 핀 검증이 우선합니다. 자체 서명을 허용하는 대신 정확히 그 키만 신뢰하므로, 사설 CA보다 좁고 강한 조건이기 때문입니다. SNI와 호스트명 검증에 쓸 이름은 TlsServerName이며, 비어 있으면 Host 값을 그대로 사용합니다.

빌드 구성에 따른 강제

항목 Development / Test Shipping
bUseTLS=False 존중됨 (연결마다 경고 로그) 무시됨 — TLS 강제
-HermesHost= / -HermesPort= 적용됨 무시됨
TLS 검증 설정의 커맨드라인 오버라이드 존재하지 않음 — 검증 정책을 실행 인자로 낮출 수 있으면 그 자체가 취약점입니다

위협 모델

무엇을 막고 무엇을 막지 않는지 명시합니다. 막지 않는 것을 막는다고 적지 않는 것이 이 표의 목적입니다.

위협 상태
player_id를 알아낸 제3자의 사칭✅ 차단 — 신원은 서버가 발급하며 session_token으로 검증
경로상 공격자의 도청✅ 차단 — TLS
경로상 공격자의 action_request 주입✅ 차단 — TLS + 인증서 검증
가짜 서버로의 유인✅ 차단 — 공개키 핀 고정 또는 CA 검증
최종 사용자의 임의 서버 리다이렉트✅ 차단 — Shipping에서 커맨드라인 오버라이드 무시
설정 실수로 인한 평문 통신✅ 차단 — Shipping에서 TLS 강제, 평문 폴백 없음
악성 피어의 클라이언트 자원 고갈✅ 차단 — 큐 상한, 틱 예산, 레이트 리밋
비정상 파라미터로 인한 크래시✅ 차단 — 파라미터 하드 바운드
기기 소유자의 세션 토큰 추출⚠️ 의도적으로 미해결
서버측 자원 고갈, 프롬프트 인젝션❌ 서버 구현 책임
세션 토큰은 암호화되지 않습니다. SaveGame에 FAES로 감싸 보관하지만 키가 바이너리 안에 있으므로 이것은 난독화입니다. 막는 것은 "세이브 파일을 그대로 복사해 남에게 넘기는" 수준까지이며, 기기 소유자로부터는 보호되지 않고 그럴 방법도 없습니다. 막는 대상은 내 player_id를 알아낸 다른 사람이지 내 PC를 뜯는 나 자신이 아닙니다.
05

JSON 메시지 타입 스펙

Message Type Direction 설명 및 주요 필드
identify Client → Server 신원 제시. protocol_version: 2(필수), player_id · session_token(재접속 시에만), player_name(optional). 최초 접속에는 두 자격 증명이 없습니다 — 신원은 서버가 발급합니다
identified Server → Client 핸드셰이크 승인 응답. ok:true, 최초 접속이면 서버가 발급한 player_id와 session_token
chat Client → Server 유저 발화 송신. id(c-0001), text
chat_delta Server → Client 스트리밍 응답 조각. id, delta. 도착할 때마다 누적 표시하며 응답 타임아웃이 갱신됩니다
chat_response Server → Client AI 응답 최종 텍스트. id, text, actions. 누적된 델타를 이 전문으로 확정합니다
action_request Server → Client NPC 행동 지시. id, command, params(JSON object)
action_result Client → Server 행동 실행 결과 회신(15초 내). id, ok(bool), result, error
action_event Client → Server 장기 실행 액션의 비동기 완료 통지. id, event(completed/failed), result. action_result는 접수만 알리고 도착 여부는 이 메시지로 옵니다
error Server → Client 서버 에러 통지. code, message, id(optional). id가 있으면 해당 발화를 즉시 실패 처리하고, 종료성 코드면 재연결 루프를 멈춥니다
ping / pong Bi-directional 연결 유지 헬스체크 핑퐁. id. 유휴 시 KeepAlivePingIntervalSeconds마다 송신하며, PeerTimeoutSeconds 동안 아무 프레임도 없으면 연결을 죽은 것으로 판정합니다
06

화이트리스트 액션 규약

📍 1. move_to
지정한 월드 좌표로 NPC를 이동시킵니다. 
// params payload
{ "location": { "x": 100.0, "y": 250.0, "z": 0.0 } }
// result: { "arrived": true }
🚶 2. follow_player
플레이어를 150cm 거리에서 지속 추적하거나 정지합니다. 
// params payload
{ "enabled": true }
// result: { "following": true }
🎒 3. inventory_manage
NPC의 인벤토리 목록을 조회하거나 아이템을 드랍합니다. 
// params: { "operation": "list" }
// result: { "items": [{"item_id":"potion","quantity":5}] }
🔄 4. item_transfer
플레이어와 NPC 간 아이템을 양도/수령합니다. 
// params payload
{ "direction": "give", "item_id": "gold", "quantity": 100 }
// result: { "transferred": 100 }
07

안전 검증 및 리소스 방어 (Safety Bounds)

서버로부터 수신된 악성 또는 비정상적인 액션 요청으로 인해 게임 로직이나 메모리가 오염되지 않도록 하드 바운드 검증 및 자원 제어가 이루어집니다.

검증 항목 하드 바운드 범위 위반 시 처리 및 회신 error
move_to 좌표 유한성 abs(v) <= 1e7 cm (MaxWorldCoordinate) 게임 로직 비실행, ok: false (coordinate out of range)
item_transfer.quantity 정수 범위 1 <= q <= 999999 게임 로직 비실행, ok: false (quantity out of range)
item_transfer.item_id 비어있지 않음 및 length <= 64 게임 로직 비실행, ok: false (invalid item_id)
액션 처리 속도 제어 토큰 버킷 레이트 리미터 (초당 최대 20회) 초과 액션 거부, ok: false (rate limited)
보류 발화 수 상한 PushBounded (MaxPendingChats=32) 미승인 세션에서 오버플로 시 가장 오래된 발화 자동 드랍
08

타 프로젝트 연동 (드래그 앤 드롭 가이드)

📂 1. 플러그인 폴더 복사
적용하고자 하는 UE 5.8 프로젝트의 루트 디렉토리에 Plugins/ 폴더를 만들고 Plugins/HermesAgentNPC/ 폴더 전체를 복사합니다.
⚙️ 2. .uproject 활성화 및 서버 주소 설정
대상 프로젝트의 .uproject 파일에 아래와 같이 플러그인을 활성화합니다. 
"Plugins": [
    { "Name": "HermesAgentNPC", "Enabled": true }
]
에디터의 Project Settings > Plugins > Hermes Agent NPC 또는 프로젝트의 Config/DefaultGame.ini에서 서버 호스트명과 포트를 설정합니다.
🎮 3. 레벨에 NPC 배치 및 사용
  1. 언리얼 에디터의 콘텐츠 브라우저 설정에서 "Show Plugin Content"를 체크합니다.
  2. HermesAgentNPC Content/NPC/BP_HermesNPC를 원하는 레벨에 드래그하여 배치합니다.
  3. 레벨 바닥에 NavMeshBoundsVolume을 배치하고, 플레이어 입력에서 BP_HermesNPC의 Interact() 메서드를 호출하면 즉시 대화가 구동됩니다.

통합 검증 체크리스트

  • Plugins/HermesAgentNPC/HermesAgentNPC.uplugin 파일의 "CanContainContent": true 설정 확인
  • 플러그인 내장 블루프린트 BP_HermesNPC 및 WBP_HermesDialogue 정상 로드 확인
  • UHermesSettings 전역 설정에서 지정한 서버 주소로 GetAddressInfo DNS 접속 및 핸드셰이크 확인
  • 최초 접속 시 서버가 player_id / session_token을 발급하고 SaveGame(HermesPlayer.sav)에 보관되는지, 재시작 후 그 자격 증명으로 재접속하며 대화 맥락이 유지되는지 확인
  • 변조된 session_token으로는 접속이 거부되는지 확인
  • 핀이 일치할 때만 TLS 연결이 성립하고, 불일치 시 사유가 로그에 남으며 평문으로 폴백하지 않는지 확인
  • move_to, follow_player, inventory_manage, item_transfer 파라미터 유효성 검증 및 15초 내 action_result 회신 확인
  • 자동화 커스텀 테스트 Hermes.* 24종 전체 통과 확인 (EXIT CODE: 0)
